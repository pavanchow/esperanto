Esperanto is a small statically-typed language with type inference, built from scratch in Rust. The part most build-your-own-language projects skip is the centrepiece here: a program that does not type-check never runs. Try it, right in your browser.

How to use this playground

Write Esperanto in the editor, or load an example with the chips. The status line above the code type-checks continuously as you type, showing the inferred type or the exact error. Press Run to evaluate a well-typed program. Try one of the broken examples to see the checker reject it with a precise message before any code executes. Everything runs in your browser.

Typed, and small enough to read

Four stages, one file each. The interesting one, the type checker, is the part you usually do not get to see.

Checked before it runs

A separate, total type-checking pass. If a program is ill-typed it is rejected with a precise message, and not a single expression executes.

Inference, not annotation soup

let bindings and every expression infer their own type. You annotate function parameters; the rest is worked out for you.

Read in a sitting

Lexer, parser, checker, and interpreter are a few hundred lines each. No bytecode, no VM, no parser generator, no dependencies.

Errors, caught before it runs

Each of these is rejected by the checker with the exact message Esperanto prints. Paste any of them into the playground above.

# each line below is rejected at type-check time, before running
true + 1;                       # arithmetic operator: expected Int, found Bool
if true then 1 else "x";        # if branches disagree: then is Int, else is Str
let f = fn(n: Int) => n; f(true);  # argument 1: expected Int, found Bool
let x = 5; x(3);                # cannot call a value of type Int

Language tour

Types, inference, functions, closures, recursion, and strings.

# comments start with '#'. statements end with ';'.
let answer = 6 * 7;                 # Int, inferred (no annotation)
let greeting: Str = "hello";        # optional annotation, checked

# parameters are annotated; the return type is optional
let add = fn(a: Int, b: Int) => a + b;

# a recursive binding declares its return type so it is in scope while checked
let rec factorial = fn(n: Int) -> Int =>
  if n <= 1 then 1 else n * factorial(n - 1);

# closures capture their scope; curried adder
let add5 = (fn(x: Int) -> (Int) -> Int => fn(y: Int) -> Int => x + y)(5);

print(factorial(10));               # 3628800
print(greeting ++ ", " ++ str(add5(add(1, 1))));  # hello, 7

How it works

Type-checking is a distinct stage. Stop after it, and an ill-typed program is reported without ever running.
